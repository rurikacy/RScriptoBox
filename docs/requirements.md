# RScriptoBox 产品需求文档

版本：0.2.0 实现规格  
日期：2026 年 10 月 15 日  
适用范围：Windows 桌面个人脚本管理工具  
配套文档：[技术设计方案](design.md)

## 1 产品结论与定位

使用 Rust 与 Tauri 2 实现本产品可行。Tauri 提供桌面界面与前后端通信，Rust 负责脚本文件、解释器检测、环境安装、进程控制和本地数据。主要工程难点是 Windows 参数解析、进程树回收、交互控制台、输出编码以及安装器的失败处理。

产品定位是“把常用脚本整理成可搜索、可配置、可直接运行的本地工具箱”。首版面向用户自己编写或明确信任的脚本，不提供脚本安全沙箱。

“一键安装”指用户在一个入口查看并确认安装计划后，由应用完成可自动完成的步骤；Windows 仍可能要求 UAC、许可确认或重启。不能承诺所有设备完全无人值守。WinGet 的安装模式、安装范围与协议参数有各自条件，详见 [WinGet 安装文档](https://learn.microsoft.com/en-us/windows/package-manager/winget/install)。

## 2 使用对象与场景

| 对象 | 主要场景 | 要解决的问题 |
| --- | --- | --- |
| 开发人员 | 构建、打包、清理、开发辅助脚本 | 不必反复查找文件、切换解释器和输入参数 |
| 运维与测试人员 | 检查、备份、部署辅助任务 | 清楚看到运行状态、退出结果和日志 |
| 个人效率用户 | 文件整理、批处理、数据转换 | 环境缺失时获得明确诊断与安装入口 |

典型流程：添加脚本 → 选择运行环境 → 保存参数 → 点击运行 → 查看结果。首次使用缺失环境时，在同一流程中完成环境准备，随后由用户再次运行脚本。

## 3 首版默认约束

以下是立项默认值，后续可根据实际使用调整。

| 项目 | 首版决定 |
| --- | --- |
| 支持目标 | Windows 10 22H2 与 Windows 11 x64，普通用户会话 |
| 当前验证状态 | 已在 Windows 10 22H2 x64 验证；Windows 11 由用户后续自行验证，不阻塞本次交付 |
| 后续平台 | ARM64、Windows Server；不支持 Windows 7、8、32 位 |
| 脚本类型 | .cmd、.bat、.ps1、.py |
| 使用方式 | 单用户、本地优先、无账号、无服务端 |
| 文件管理 | 复制入口到工作台，执行与编辑副本；按相对路径携带，不自动复制依赖项目 |
| 执行权限 | 默认当前用户权限；首版不提供集成管理员执行 |
| 网络需求 | 管理和运行已有环境可离线；环境下载和依赖安装需要网络 |
| 环境安装范围 | CMD 检测，PowerShell 7 安装，Python 管理器及解释器安装 |
| 自动执行 | 导入、启动应用、安装完成均不自动执行业务脚本 |

CMD 是 Windows 自带解释器，无需另装；脚本调用的 Git、Java、FFmpeg 等外部工具可能仍需自行安装。Windows PowerShell 5.1 与 PowerShell 7 必须分别管理，不能视为同一产品的可互换版本。参考 [CMD 文档](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/cmd) 与 [PowerShell Windows 安装文档](https://learn.microsoft.com/en-us/powershell/scripting/install/install-powershell-on-windows)。

## 4 范围与优先级

P0 是首版交付要求，P1 是首版之后的增强，P2 是明确延后的独立项目。

| 模块 | P0 | P1 或 P2 |
| --- | --- | --- |
| 脚本库 | 多文件添加、拖入、移除记录、重定位、备注、标签、收藏、搜索筛选 | P1 文件夹批量扫描、配置导入导出 |
| 执行配置 | 参数列表、工作目录、环境变量、解释器绑定、超时、运行模式、输出编码 | P1 同一脚本多套命名配置 |
| 运行任务 | 启动、状态、强制停止、受控并发、退出结果 | P1 排队、全局热键、托盘快捷启动 |
| 运行界面 | ConPTY 内置交互终端、独立系统控制台模式 | P2 更完整的终端扩展 |
| 环境中心 | 检测、选择、安装、复检、手动登记、诊断 | P1 无 WinGet 时自动调用官方安装包、离线安装包 |
| Python 依赖 | 创建专用 venv、显式安装用户选择的 requirements.txt、查看失败日志 | P1 pyproject 工作流、uv 或 Conda 深度集成 |
| 历史与存储 | 运行历史、日志回放、保留期限、配额、数据库备份恢复 | P1 打包迁移和路径映射 |
| 系统集成 | 打开脚本目录、使用系统关联编辑器编辑、单实例 | P1 开机启动、系统右键菜单 |
| 高级能力 | 不纳入首版 | P2 管理员辅助进程、计划任务、工作流、插件市场、云同步 |

首版不做内置 IDE、任意语言环境安装器、自动分析 import 并安装依赖、脚本市场、自动更新系统运行时，以及自动修改系统安全策略。

## 5 功能需求

### 5.1 脚本库

| 编号 | 需求 | 验收要求 |
| --- | --- | --- |
| SCR 01 | 文件选择与拖入支持多个允许的脚本扩展名 | 不支持的文件逐项提示；已登记的同一文件不会重复添加 |
| SCR 02 | 保存名称、副本相对路径、来源路径、类型、备注、标签、收藏和时间 | 名称默认取文件名，可修改展示名称 |
| SCR 03 | 按名称、路径、备注和标签搜索 | 可叠加类型、收藏、文件状态筛选 |
| SCR 04 | 副本丢失时显示“副本不存在” | 禁止启动；可重新导入副本，不静默删除记录 |
| SCR 05 | “移除”只删除管理记录 | 原始脚本、工作台副本及同目录数据不受影响；历史保留脚本名称快照 |
| SCR 06 | 打开所在目录、调用系统编辑动作 | 只使用 edit 关联，缺失时提示；禁止用默认打开动作代替编辑，避免执行脚本 |
| SCR 07 | 首次执行与文件变化提示 | 展示路径、解释器和执行权限；文件变更后撤销已记住的确认 |

默认不递归扫描全盘，不监视整个文件系统。列表刷新或运行前检查工作台副本是否存在、是否变更。原文件删除不影响已导入副本。

文件 SHA256 用于变更提醒，只覆盖入口脚本，不能证明整个项目及依赖安全，也不能取代操作系统隔离。

### 5.2 执行配置

每个脚本首版保存一套默认配置；单次运行允许临时覆盖，用户明确点击保存后才成为新默认值。

| 配置 | 默认与规则 |
| --- | --- |
| 解释器 | 明确绑定解释器记录；默认选择只用于初次配置，不随系统 PATH 变化静默换版本 |
| 参数 | 一项一个参数；允许空参数；显示命令预览，预览不能直接成为执行输入 |
| 工作目录 | 脚本所在目录；允许另选现有本地目录 |
| 普通环境变量 | 继承当前用户环境并覆盖选定键；只影响本次子进程 |
| 敏感输入 | 保存参数位置或环境键、敏感标记和是否必填，本次值仅保存在内存；不保存默认值和历史明文 |
| 超时 | 默认无限；可设置正整数秒；按整个任务生命周期计时 |
| 运行模式 | 内置终端为默认，两种模式都支持交互 |
| 编码 | 内置终端固定 UTF-8；旧版日志保留 UTF-8、系统代码页、GB18030 回放 |
| 成功退出码 | 默认仅 0；可保存明确的退出码集合 |
| PowerShell 引擎 | Windows PowerShell 5.1 或 PowerShell 7；不自动回退另一个引擎 |

CMD 的参数和文件路径要经过专用适配。首版保证普通路径、空格、中文和空参数；含有不支持的 shell 元字符时执行前明确拒绝，不能尝试后继续运行。具体支持范围与验证门槛见技术设计。

首版只接受本地磁盘路径。UNC、设备路径及超过受测长度范围的路径应明确报不支持，避免依赖 CMD 和其他工具不一致的路径语义；长路径兼容作为后续增强。

### 5.3 运行任务

| 编号 | 需求 | 验收要求 |
| --- | --- | --- |
| RUN 01 | 点击运行先检查文件、环境、配置和确认状态 | 缺失解释器、工作目录或不合法参数时，不启动进程 |
| RUN 02 | 同时最多运行 4 个任务 | 同一脚本默认不允许重入；达到上限提示，不静默丢弃操作 |
| RUN 03 | 实时展示状态、开始时间、耗时和根进程退出码 | 区分启动失败、非零退出、用户停止、超时和异常中断 |
| RUN 04 | 停止整个受控任务树 | UI 标注“强制停止”；仅结束主进程不算验收通过 |
| RUN 05 | 超时与手动停止使用相同生命周期管理 | 重复点击和退出竞争不会产生多个终态 |
| RUN 06 | 根进程退出但受控子进程仍在运行 | 显示“等待子进程结束”；不提前记录整个任务完成 |
| RUN 07 | 应用退出时处理任务 | 提供返回应用或停止任务后退出；应用异常退出后清理 Job 内任务 |
| RUN 08 | 应用重启恢复历史状态 | 原活动记录标记为“异常中断”，不根据旧 PID 接管或终止其他进程 |

成功表示根进程返回配置的成功码，且受控进程组已结束。stderr 有内容不直接等于失败；PowerShell 的非终止错误也不一定产生非零退出码。脚本作者需要自行表达业务成功或失败。

Job Object 用于正常进程树的生命周期管理。脚本委托系统服务、计划任务等外部代理启动的工作，可能不属于该任务树；产品不能承诺终止任意外部副作用。见 [Windows Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)。

### 5.4 两种运行模式

| 行为 | 内置终端模式 | 系统控制台模式 |
| --- | --- | --- |
| 输出 | 应用内实时日志与历史回放 | 显示在 Windows 控制台，无输出历史 |
| 输入 | 通过 ConPTY 支持行输入、按键、隐藏密码与 Ctrl+C | 支持 input、Read-Host、pause 等控制台输入 |
| 退出结果 | 保存状态与退出码 | 保存状态与退出码 |
| 应用停止按钮 | 强制结束 Job 内进程；Ctrl+C 交给脚本 | 相同；用户也可在控制台自行按 Ctrl+C |
| 窗口结束行为 | 日志仍可查看 | 进程结束后控制台可能立即关闭，不自动追加 pause |
| 提权 | 首版不支持 | 首版不支持 |

控制台由 Windows 承载，不保证特定 Windows Terminal 标签页布局。用户手动关闭控制台的原因无法可靠识别，记录实际退出情况，不直接归类为应用内“用户停止”。

### 5.5 日志与历史

1. 内置终端使用 ConPTY 合并输出，支持无换行提示、回车重绘和多字节字符跨块。旧版 captured 记录仍按独立双流回放。
2. 终端输出由 xterm.js 渲染 VT 控制序列，不启用打开链接和剪贴板扩展；文件名与普通错误消息按纯文本展示。
3. 支持暂停界面滚动、复制、按运行查看及导出日志。暂停滚动不暂停后台采集。
4. 保留原始字节，终端历史固定 UTF-8，旧版双流可切换编码；终端日志导出保留控制序列，复制提供当前显示的纯文本。
5. 默认每次日志总量上限 20 MiB；达到上限显示“日志已截断”，继续读取并丢弃后续持久化内容，脚本可继续运行。
6. 历史日志默认保留 30 天，总量上限 500 MiB，包含安装诊断日志；先清理最旧已结束任务，不清理活动任务文件。没有可清理文件时停止后续持久化并标记截断，继续排空输出。
7. 界面只保留最近 10,000 行或 2 MiB 文本，先触及者生效；更早内容分页从磁盘读取。
8. 存储设备写入失败时强制停止日志模式任务，保留已写内容并显示存储错误，不能无限积压到内存。
9. 已标注的敏感输入不写入执行计划和元数据；脚本主动输出的敏感内容仍可能进入原始日志。导出前提示检查。

安装诊断日志同样设置单次 20 MiB 上限；写盘失败时停止保存诊断并提示，不因此强杀外部安装器。脚本任务和外部安装器采用不同的失败处理。

### 5.6 环境中心

| 对象 | 检测与操作 | 不允许的默认行为 |
| --- | --- | --- |
| CMD | 检测系统解释器与可启动性 | 显示“安装 CMD”或下载第三方 cmd.exe |
| Windows PowerShell 5.1 | 单独登记系统引擎，检查策略与版本 | 卸载、替换系统引擎 |
| PowerShell 7 | 发现已有 pwsh，缺失时提供安装计划 | 将所有 ps1 静默切换到 7 |
| Python | 发现已有解释器、版本、架构和虚拟环境 | 只因 PATH 有 python 字样就视为可用 |
| 手动环境 | 用户选择实际解释器，验证后登记 | 自动接管或卸载用户的 Conda、venv 或其他安装 |

环境记录区分“检测到”“验证可用”“不可用”“需要复检”。运行前复核绑定路径，环境失效时禁止静默改用另一版本。

#### 安装流程

检测 → 展示安装计划 → 用户确认 → 下载或调用安装器 → 处理系统交互 → 复检 → 就绪或给出可操作错误。

计划显示产品、版本选择、来源、架构、用户或机器安装范围、许可与可能的权限要求。无法预估的下载大小不显示伪精确值。

首版使用受维护的 WinGet 安装配方。无 WinGet、源不可达或企业禁用时，提供官方下载入口和手动登记；自动下载官方独立安装器作为 P1。不能偷偷改源、绕过校验或关闭企业策略。

Python 分两层验证：先确认官方 Python Install Manager 可用，再确认用户选定的 Python 运行时可用。自动化使用 pymanager，实际运行脚本使用解析后的 python.exe 绝对路径，避免旧 py 启动器冲突和运行时的隐式下载。见 [Python Windows 官方指南](https://docs.python.org/3/using/windows.html)。

安装完成后重新发现文件路径和运行能力，不要求用户为刷新 PATH 而重启整个应用。失败至少区分网络问题、用户拒绝 UAC、策略限制、版本不适用、需要重启和未知结果。

安装任务与脚本任务分开管理。调用外部安装器后不能保证取消会立刻停止或回滚；界面应保留“正在安装”或“结果待复检”，不能仅杀掉 winget 就宣称取消成功。全局同时只允许一个环境变更任务，跨应用重启也保留未决锁，复检确认后才放行。

首版不提供系统运行时卸载、自动升级或自动降级。应用卸载也不顺带删除用户的 Python、PowerShell 和原始脚本。

### 5.7 Python 依赖

1. 无依赖脚本可直接绑定已有解释器运行。
2. 需要隔离时，为脚本创建应用拥有的 venv；也允许绑定用户已有 venv 的解释器。
3. requirements.txt 由用户明确选择并查看路径后安装；发现文件不等于同意安装。
4. 始终使用目标环境的 python.exe -m pip，不使用全局 pip，不要求用户激活环境；禁用会改变安装目标的继承配置，防止包被意外装到环境之外。
5. requirements.txt 可能包含网络地址、本地路径和构建步骤；安装前告知会下载并执行第三方安装逻辑。
6. 安装期间锁定该环境，禁止并行运行依赖它的脚本。失败时标记依赖状态未知或失败，不显示“环境已准备完成”。
7. venv 通过独立创建和验证后才绑定；已有正常环境不原地删除重建。重建需用户明确选择。
8. 不根据 import 自动猜包，不自动装 C/C++ 编译工具、系统驱动或任意 PowerShell 模块。

venv 的解释器可直接调用，不需要 activate；虚拟环境应在迁移后重建，不能当作可移动备份。见 [Python venv 文档](https://docs.python.org/3/library/venv.html)。

### 5.8 设置与数据维护

提供默认运行模式、并发上限 1 至 4、日志配额与保留期、编码默认值、环境重新检测和数据目录入口。

数据库迁移前自动备份，保留最近 3 份。提供备份与恢复入口；恢复前停止活动脚本任务，未决环境安装必须先完成复检，再关闭数据库连接。恢复失败保留当前数据。备份包含配置与记录，不包含源脚本、系统解释器和虚拟环境。

应用卸载默认保留用户数据；若提供清除数据选项，必须明确列出范围。删除记录和清理日志都不得删除源脚本。

## 6 页面与交互

| 页面 | 内容 | 核心操作 |
| --- | --- | --- |
| 脚本库 | 搜索、类型与标签筛选、脚本列表、环境状态 | 添加、收藏、运行、配置、打开目录、移除 |
| 脚本详情 | 说明、路径、执行配置、最近结果 | 保存配置、选择环境、普通或控制台运行 |
| 任务与日志 | 活动任务、状态、耗时、输出 | 强制停止、切换任务、复制或导出 |
| 环境中心 | 已安装环境、绑定情况、缺失项 | 检测、安装、指定路径、创建 venv、安装依赖 |
| 历史 | 时间、脚本、解释器、结果和日志状态 | 筛选、查看、导出 |
| 设置 | 配额、并发、默认值、备份恢复 | 修改、备份、恢复、打开数据目录 |

列表中的“运行”执行已保存配置；缺少参数、未确认的脚本或环境不满足条件时，打开对应配置，不直接执行。

“安装环境”与“运行脚本”是两次可辨认的操作。安装成功后展示“环境已就绪，可以运行”，不自动执行先前脚本。

核心路径应支持键盘操作、可见焦点和状态文字；颜色只作辅助。首版提供简体中文界面，至少支持 1280×720 与 100% 至 200% 缩放。

## 7 异常处理要求

| 情况 | 用户可见行为 |
| --- | --- |
| 文件被移动 | 保留记录，提示重新定位 |
| 解释器被删除 | 标记环境不可用，提供重新绑定或安装 |
| ps1 被策略阻止 | 显示可获得的策略范围与诊断，不永久修改系统策略 |
| PS 5.1 中文源码编码不兼容 | 提示 UTF-8 BOM 等兼容要求，不自动改写源文件或切换引擎 |
| Python 缺少模块 | 保留原始错误，提供依赖设置入口，不猜测并自动装包 |
| CMD 参数不受支持 | 指出具体字段与字符，启动前拒绝 |
| 磁盘已满 | 停止受影响日志任务，显示存储错误；数据库也失败时用原生提示兜底 |
| 安装过程被打断 | 下次启动重新检测，不直接显示成功或已回滚 |
| 依赖安装失败 | 环境暂不可运行，提供日志、重试与显式重建 |
| 运行需要管理员权限 | 提示首版不支持集成提权，不重启整个应用为管理员 |
| 数据库损坏或新版本不兼容 | 不覆盖为新空库，提供错误和备份恢复入口 |

PowerShell 默认遵循机器现有执行策略。可提供明确的“仅本次进程”策略选择，但不能覆盖组策略，也不能自动永久降低策略或解除文件来源标记。见 [执行策略说明](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_execution_policies)。

## 8 非功能需求

以下是首版验收目标，不是当前已测结果。基准机采用 Windows 11 x64、4 核 CPU、16 GB 内存、SSD，预先安装 WebView2；运行性能不计业务脚本本身的耗时。

| 项目 | 验收目标 |
| --- | --- |
| 冷启动 | 启动至脚本列表可操作不超过 3 秒，环境扫描异步进行 |
| 列表与搜索 | 1,000 条脚本记录下，搜索完成 p95 不超过 200 ms |
| 运行启动 | 本地环境已验证时，点击至进入启动或运行状态 p95 不超过 500 ms |
| 日志延迟 | 子进程已经 flush 的正常输出，界面显示 p95 不超过 250 ms |
| 高输出负载 | 单任务 1 MiB/s、持续 60 秒，配额生效且界面可操作，不无限增长内存 |
| 进程停止 | 普通本地任务点击停止后 3 秒内确认 Job 清空；异常系统情况给出未完成状态 |
| 数据可靠性 | 操作使用事务；迁移失败、写盘失败和崩溃恢复不静默丢弃已有脚本记录 |
| 隐私 | 默认无遥测，不上传脚本、日志、路径或运行参数 |
| 安全边界 | 后端验证所有执行输入；前端无通用任意 shell 调用权限 |

应用安装器必须处理 WebView2 缺失。在线包检测并引导安装；可在 P1 提供包含 WebView2 的离线包，不能承诺完全离线的一键准备所有脚本环境。见 [Tauri Windows 安装器](https://v2.tauri.app/distribute/windows-installer/)。

## 10 开发计划与交付

按一名熟悉 Rust 和前端的开发者估算，P0 约 5 至 8 人周；Windows 进程控制或安装兼容性问题可能扩大周期。该估算需在技术验证完成后修订。

| 阶段 | 主要产物 | 完成条件 |
| --- | --- | --- |
| 技术验证，约 1 周 | 四类脚本最小执行器、Job 回收、两种模式、安装探针 | A02、A03、A09、A11、A17 的核心用例通过 |
| 脚本库与配置，约 1 周 | 界面、数据库、添加搜索、解释器绑定 | 管理与执行形成完整本地流程 |
| 运行与日志，约 1 至 2 周 | 状态、历史、编码回放、配额、异常恢复 | 负载与生命周期用例通过 |
| 环境与依赖，约 1 至 2 周 | WinGet 配方、Python 管理器、venv、诊断 | 干净系统与失败场景通过 |
| 发布验收，约 1 至 2 周 | 便携包、备份恢复、用户说明 | P0 用例通过，无已知阻断问题 |

阶段工作可交叠；上表不是固定日历承诺。

交付包含 Windows x64 独立 EXE 与便携 ZIP、源代码、运行与安装兼容性记录、用户使用说明、环境配方版本及验收结果。按用户明确要求，本次不做数字签名；通过手动替换程序升级。自动更新与完整离线环境发行另行排期。

首个开发里程碑应验证 Windows 执行层和环境安装；这两部分决定可靠性，再在其上完成界面。
